# Intake and Routing Reference

Use this file when you need to quickly frame the problem before choosing a deeper module.

## 1) Classify the business

Pick the closest fit:

- SaaS / software
- Ecommerce / DTC
- Local business
- Multi-location business
- Publisher / media
- Marketplace
- B2B services / agency / consultancy
- Healthcare / legal / regulated
- Nonprofit / education
- Support/docs/help center

## 2) Classify the objective

Identify the primary job:

- grow nonbrand demand
- protect or recover rankings
- launch or expand into new topics / markets
- improve lead quality or revenue from organic
- support local pack / map visibility
- fix technical debt or migration risk
- scale editorial production
- build internal systems and reporting
- turn SEO into an agency/client operating cadence

## 3) Classify the request type

### Use Strategy Mode when:
- the user needs a roadmap, prioritization, or page strategy

### Use Ranking Engine Mode when:
- the user asks why traffic or rankings moved
- the user wants to understand what the SERP rewards
- the user needs page-to-query or entity fit analysis

### Use Content Factory Mode when:
- the user needs clusters, briefs, outlines, refreshes, or consolidation rules

### Use Technical Mode when:
- the issue smells like crawl, render, indexation, canonicals, faceted navigation, migration, schema, or performance

### Use Internal Linking + IA Mode when:
- the site has orphan pages, weak service/category support, poor crawl depth, or messy architecture

### Use Authority + Digital PR Mode when:
- the user needs link earning, mention generation, or trust amplification

### Use Local Mode when:
- the user needs GBP strategy, location-page plans, review systems, or service-area execution

### Use Reporting + Experimentation Mode when:
- the user needs dashboards, KPI logic, or validation plans

### Use Agency OS Mode when:
- the user needs audit deliverables, sprints, owner mapping, or retainer workflows

## 4) Minimum viable diagnosis

Even with partial data, try to define:

- current symptom
- likely cause class
- pages affected
- queries affected
- geography/device patterns
- timeline
- most plausible next validation step

## 5) What to infer if missing

If the user omits details, infer sensible defaults:

- page intent from the query
- business model from the product/service
- likely conversion event from the site type
- likely page archetype from the SERP
- likely owner from the workstream (content, dev, SEO, local ops, analytics)

## 6) Page archetypes

Use these often:

- homepage
- category / collection page
- service page
- location page
- comparison page
- solution / use-case page
- product page
- blog / guide
- template / calculator / tool
- docs / help article
- profile / directory page

## 7) Default structure for recommendations

For any recommendation, try to specify:

- what to change
- where to change it
- why it matters
- who owns it
- what dependency exists
- what KPI should move first
