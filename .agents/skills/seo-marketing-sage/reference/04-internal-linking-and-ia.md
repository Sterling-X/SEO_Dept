# Internal Linking and IA Reference

Use this file for information architecture, hub/spoke design, contextual links, crawl depth, orphan recovery, and page support systems.

## 1) Core principle

Internal links are not decoration. They shape:
- discovery
- crawl efficiency
- topical neighborhoods
- relevance reinforcement
- user navigation
- conversion paths
- consolidation of importance

## 2) Architecture questions

Always ask:
- can key money pages be reached in few clicks?
- do hubs point to children and children link back?
- are there obvious orphan or near-orphan pages?
- does the structure reflect the business, not just the CMS?
- are service/category pages supported by guides, comparisons, FAQs, locations, or docs?
- do contextual links carry more useful intent than nav/footer links alone?

## 3) Internal link recommendation format

Every recommendation should specify:
- source page
- target page
- anchor theme
- placement type: nav, footer, in-body, related block, hub table, CTA, breadcrumb
- reason for the link
- expected effect: discovery, relevance, conversion, consolidation

## 4) Hub and spoke models

Useful patterns:
- category -> subcategory -> product
- service -> subservice -> industry/use-case
- location -> service-in-location -> nearby markets
- guide -> comparison -> money page
- docs hub -> feature docs -> solution page
- stats page -> editorial support -> commercial page

## 5) Anchor rules

Prefer anchors that are:
- descriptive
- natural in sentence context
- aligned to destination purpose
- varied but consistent by theme
- useful to humans, not just search engines

Avoid:
- manipulative exact-match repetition
- generic “click here” where clarity matters
- links that do not match destination intent

## 6) Quick-win internal-link sprints

High-leverage sprints often include:
- add links from top-traffic blog posts to core money pages
- connect comparison content to the right category/service pages
- surface orphaned but valuable URLs
- create parent hub pages for scattered content
- add breadcrumb and related-link systems
- reclaim links pointing to redirected or deprecated URLs

## 7) When IA is the real problem

Symptoms:
- many pages exist but few rank
- important pages are buried
- template-driven sprawl outnumbers strategic pages
- multiple pages target the same term without hierarchy
- users and bots have no obvious path to the best page

Fixes:
- reduce duplication
- create hierarchy
- define canonical targets
- establish hub pages
- improve navigation labels
- use contextual links intentionally

## 8) Deliverables

Good outputs from this module:
- internal-link plan
- hub/spoke map
- source/target matrix
- orphan recovery list
- architecture revision proposal
- navigation relabeling suggestions
