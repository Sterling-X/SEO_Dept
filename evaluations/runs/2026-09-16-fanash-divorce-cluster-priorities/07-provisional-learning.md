# Provisional Learning Record

Status: **provisional — not adopted into shared instructions or skills**

## Trigger

The frozen strategist's first action grouped every unresolved cluster question into one decision packet. The independent reviewer correctly identified a risk: evidence for excluded Collaborative and Military branches could be read as a blanket prerequisite for publishing a Hub that does not activate those branches.

## Proposed general lesson

> For a completed hub, separate hard launch gates from parallel branch validation. Only unresolved facts that affect activated claims, links, implementation choices, or the pre-change snapshot should block release; evidence for excluded branches should be collected without becoming a blanket blocker.

## Evidence demonstrated here

- The Fanash Hub activates eight children, so current acceptance for those routes, the selected phone/market framing, and the pre-change snapshot affect release.
- `FL-M003` and `FL-M025` are excluded, so unresolved capability or demand evidence for those branches does not invalidate the Hub.
- `FL-M008` and `FL-M026` are also excluded pending repair; their defects govern later link activation rather than blocking the current Hub proposal.

## Action taken

The final plan narrows Action 1 to the hard gates and allows implementation preparation in parallel. This record is the only persistence action. No architecture, context principle, shared skill, application, validator, workflow, or existing deliverable was changed.

## Validation needed before adoption

Test the rule on at least two future hub evaluations selected in advance:

1. one case where an activated child has unresolved service evidence and therefore should block release; and
2. one case where an excluded child remains unresolved but the Hub should proceed.

The lesson should be rejected or revised if it allows an unsupported activated claim/link or if it makes a clearly independent excluded branch delay release. Until then, it remains a bounded hypothesis from one Fanash evaluation.
