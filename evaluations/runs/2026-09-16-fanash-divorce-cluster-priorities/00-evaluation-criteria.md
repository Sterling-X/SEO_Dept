# Fanash Divorce Cluster Priority Evaluation

Date: 2026-09-16  
Client: Fanash Family Law, P.A.  
Cluster anchor: `FL-PA-DIV`  
Status: Criteria frozen before the independent review was opened

## Capability being evaluated

Prioritize the next five SEO actions for one family-law content cluster by combining governing architecture, client-specific evidence, implementation readiness, business risk, and measurement value. The capability is prioritization under uncertainty, not page production or architecture design.

## Why this example represents the capability

Fanash has a completed but unpublished Core Hub proposal, several live child pages, two documented destination defects, one required but unverified service branch, one conditional branch with incomplete demand evidence, and no performance or intake dataset in scope. The case therefore tests whether architecture status is weighed as one input instead of being mistaken for business priority.

## User decision and completion condition

The user needs five ordered actions and the evidence needed to change that order. Completion requires:

1. a frozen strategist ranking;
2. an independent `seo_reviewer` ranking produced from the same evidence before it sees the strategist ranking;
3. an evidence-based comparison and reconciliation;
4. a concise final five-action plan; and
5. any reusable lesson recorded only as provisional.

## Fixed criteria

| Criterion | Passing condition |
|---|---|
| Business relevance | The action addresses a documented user path, service decision, live defect, or measurement gap without inventing demand, traffic, leads, conversions, or revenue. |
| Evidence strength | Direct Fanash and V2 evidence is separated from hypotheses and unknowns. Known defects generally outrank speculative expansion unless a documented dependency changes that result. |
| Architecture fidelity | Every recommendation preserves the V2 node, role, requiredness, gate, and exact direction. Required status alone is not treated as business priority. Missing relationships are described as unspecified, not automatically prohibited. |
| Client-offer fidelity | Published first-party claims are not converted into current intake acceptance, credentials, neutral-mediator status, pricing, or service promises. |
| Sequencing and effort | The order accounts for prerequisite decisions, implementation readiness, risk, effort, and whether a repair or existing completed asset can produce a signal before net-new production. |
| Measurability | Every action has an observable completion check and, where relevant, a later outcome signal. Diagnostic SEO measures are not substituted for qualified-inquiry outcomes. |
| Scope discipline | No new page is written; no broad crawl, architecture change, shared-skill change, application change, website change, publication, commit, or push is performed. |

## Inclusion boundary

Included: the completed Core Hub proposal, scoped Fanash child destinations and facts already captured in its supporting evidence, exact V2 nodes and relationships needed for the divorce cluster, local workflow-readiness limits, and precise missing data that could change priority.

Excluded: new live research unless existing evidence proves inadequate, competitor research, keyword-volume estimates, broad crawl findings, backlink analysis, forecasts, and any implementation or publication.

The criteria remain fixed during reconciliation. New evidence may change a priority, but agreement between agents does not establish correctness.
